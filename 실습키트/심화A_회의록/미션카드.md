# 심화 A — 회의록 스킬: 고치는 곳은 세 군데뿐

> 목표: 회의록 스킬을 설치하고, 우리 조직에 맞게 3곳을 수정한 뒤, 샘플 녹취록으로 실행해 [확인] 태그를 검토한다.

## 1. 설치 — 폴더 복사가 곧 설치

```bash
cp -r 실습키트/심화A_회의록/skills/meeting-minutes ~/.claude/skills/
```
(또는 Claude Code에 "이 폴더의 meeting-minutes 스킬을 내 스킬 폴더에 설치해줘")

## 2. 수정 — SKILL.md 안의 ▢ 표시 3곳

파일을 열면 맨 아래 `▢ 조직 맞춤 1·2·3` 주석이 있습니다:
1. 참석 구분 표기 (내부/외부 전문가/간사 …)
2. 후속조치 '담당' 표기 규칙 (부서명+성명? 직급 포함?)
3. 우리 조직의 민감 기준 추가

> 스킬 만들기 = 코딩이 아니라 **업무 매뉴얼 작성**입니다. 문장으로 적을 수 있으면 규칙이 됩니다.

## 3. 실행

```
sample_회의녹취록.txt와 sample_개최안.md 읽고 meeting-minutes 스킬로 회의록 초안 만들어줘
```

## 4. 검토 — 이렇게 나오면 성공 (정답 힌트)

샘플 녹취에는 의도적으로 심어 둔 요소들이 있습니다. 초안에서 확인해 보세요:
- **결정사항 3건** — ①7월호 자동 조판 대조 후 8월호 본 적용 ②JCR 외부 조사에 저널명·ISSN만 사용(원칙 확정) ③사용 가이드 작성 분담
- **미결사항 2건** — 자문위원회 일정(위원 회신 대기) · 다음 기획회의 일자
- **후속조치 표** — A연구원(대조 결과, 수요일) / C연구원(가이드 초안) / B책임(보안 수칙 검토)
- **[확인] 태그가 붙어야 할 곳** — "다음 기획회의 전까지"(기한 불명확), "아흔두 건"(수치), 참고: 화자는 명확한 편
- 초안 끝의 **검수 체크리스트** 자동 첨부

결정으로 승격되면 안 되는 것: "부서 가이드를 만들면 좋겠다"는 **제안 발언**이 아니라 좌장의 "그렇게 하죠"로 **결정**이 된 것 — 이 구분이 스킬의 판별 규칙입니다.

## 5. 실전 적용

실제 회의에 쓸 때: TIRRO에서 전사 텍스트 내보내기 → 개최안과 함께 폴더에 → 같은 명령.
⚠ 비공개 회의 녹취의 외부 서비스 업로드는 기관 규정을 먼저 확인하세요.
