# 실습 5 — 스킬 만들기: 회의 개최 계획(안) 작성 스킬

> **목표**: 내 판단 기준을 파일로 적어 스킬을 만들고, **기준 없을 때와의 차이**를 눈으로 확인한다.
> **소요**: 35분
> **핵심 메시지**: 내 판단 기준을 문서화하면 **뭐든 스킬이 된다**

---

## 5-1. 먼저 '그냥' 시켜 보기 (Before, 5분)

```
다음 달 소재기술 기획회의 개최 계획(안) 하나 써줘
```

결과를 **닫지 말고 그대로 두십시오.** 그리고 아쉬운 점 **세 가지**를 메모합니다.

흔히 나오는 것:
- 항목이 우리 양식과 다름 (필요한 항목 누락 / 안 쓰는 항목 추가)
- 어투가 보고서체·설명체 (우리는 개조식·공문 톤)
- **없는 정보를 지어냄** (실재하지 않는 위원회명, 임의의 예산·시간)

> 대부분 여기서 "역시 실무엔 안 되네"라고 결론 냅니다. **기준을 안 줬을 뿐입니다.**

---

## 5-2. 내 기준을 스킬 파일로 (15분)

```
meeting-plan 스킬을 만들어줘. ~/.claude/skills/meeting-plan/SKILL.md 로.
회의 개최 계획(안)을 쓰는 스킬이고, 아래를 반드시 넣어줘.

① 출력 항목: 회의명 / 일시·장소 / 개최 목적·배경 / 안건표(순번·안건·발표자·소요시간)
   / 참석 대상 / 준비·배포 자료 / 협조 요청 / 붙임
② 판단 기준: 안건은 3건 이내 · 안건당 기본 15분(발표10+질의5)
   · 총 90분 초과 시 경고 · 목적은 '무엇을 결정하는 회의인지' 한 문장으로
③ 금지: 위원 이름·기관명·예산 숫자를 지어내지 말 것 — 모르면 [확인: 항목명]으로 비워둘 것
④ 어투: 개조식, '~함/~임' 종결, 공문 톤, 과장 표현 금지
```

**그다음이 진짜 실습입니다** — 생성된 SKILL.md를 열어 **내 말로 고칩니다**:
- 우리 부서가 실제로 쓰는 항목 이름으로
- 우리 회의 시간 규칙으로 (예: 자문회의는 120분, 안건당 20분)
- 우리가 자주 빠뜨리는 것을 금지 규칙에 추가

> 완벽할 필요 없습니다. **쓰면서 한 줄씩** 늘리는 것이 정석입니다.

**✅ 성공 판정**: SKILL.md에 **항목 · 기준 · 금지 · 어투** 네 덩어리가 있다

---

## 5-3. 같은 요청, 이번엔 스킬로 (After, 10분)

```
meeting-plan 스킬로 다음 달 소재기술 기획회의 개최 계획(안) 써줘.
참석 대상은 내부 5명·외부 위원 3명, 안건은 기획방향 검토와 일정 확정.
```

**5-1의 결과와 나란히 놓고 비교합니다.**

| 5-1 (기준 없음) | 5-3 (스킬 적용) |
|---|---|
| 항목이 우리 양식과 다름 | 8개 항목이 양식대로 |
| 어투가 보고서체 | 개조식·공문 톤으로 통일 |
| 없는 위원회명·예산을 지어냄 | 모르는 건 `[확인: 위원 명단]`으로 비움 |
| 결국 손으로 다시 씀 | 시간 배분까지 자동 계산 |

**✅ 성공 판정**: 두 산출물의 차이를 **세 가지 이상** 셀 수 있다

> 모델은 같습니다. 달라진 건 **내가 쓴 파일 한 장**뿐입니다.

---

## 5-4. (확장) 같은 뼈대로 검토의견서 스킬

실습 4에서 분류한 수요조사서 1건을 입력으로 씁니다.

```
review-opinion 스킬을 만들어줘. 수요조사서 1건을 받아 기획 검토의견서를 쓰는 스킬.
① 항목: 기술분류 / 중복성 / 시급성 / 파급효과 / 종합의견·검토등급
② 기준: 중복성은 기존 과제·클러스터 대조 근거가 있을 때만 '중복' — 추정 금지
   시급성은 정책 근거(계획·공고·법령)를 인용할 것
   파급효과는 정량 근거 없으면 '정성'이라 명시
③ 금지: 점수·등급을 근거 없이 매기지 말 것 — 판단이 갈리면 [검토자 판단 필요]
④ 어투: 개조식, 단정 표현 자제('~로 판단됨')
```

실행할 때 **실습 4의 `02_클러스터.md`를 함께 주면** 중복성 판단에 실제 근거가 붙습니다:

```
review-opinion 스킬로 수요조사서/07_반도체_....md 를 검토해줘.
중복성 판단은 실습4_수요조사/02_클러스터.md 를 근거로 해.
```

## 스킬로 만들 만한 것 — 판단 기준 두 가지

| 질문 | 예라면 |
|------|--------|
| **반복되는가?** | 절차를 파일로 굳힌다 (스킬) |
| **틀리면 큰일 나는가?** | 검증자를 붙인다 (검수 규칙·팀) |

둘 다 예 → 스킬 + 검수 규칙. 회의 개최안, 회의록, 검토의견서, 결과보고,
보도자료, 공고문 검토 — **틀이 있는 문서는 전부 후보**입니다.

## 막혔을 때

| 증상 | 처방 |
|------|------|
| 스킬이 발동하지 않는다 | 스킬 이름을 명시(`meeting-plan 스킬로 …`) · Claude Code 재시작 |
| 파일 위치를 모르겠다 | `방금 만든 스킬 파일 경로 알려줘` |
| 결과가 여전히 아쉽다 | **그 아쉬움을 SKILL.md에 한 줄 추가** — 이것이 이 방법의 전부입니다 |
